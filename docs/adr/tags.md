# Decision record tags

Each record carries one or more tags on its `Tags` line, from the table below. A tag names a
subject a decision touches, and a record may carry tags from any area, so a decision that binds
several subjects is found under each. A record's first tag is the area word its title starts
with.

To add a tag, add a row here and run `node scripts/adr.ts --write`. A tag no record carries is
reported, so the table lists only tags in use.

| Tag | Covers |
|---|---|
| `2d` | the batched quad pipeline and the canvas that draws through it |
| `animation` | keyframes, clips and their playback |
| `apps` | how an app is built on the api: its startup, its shell, and its pictures |
| `assets` | loading assets, and the loaders registered for each kind |
| `audio` | sound playback and its back ends |
| `build` | CMake, packages, compilers and how other projects consume the api |
| `camera` | projection, handedness and camera profiles |
| `ci` | the continuous integration jobs |
| `code` | rules for C++ code |
| `colour` | colour spaces, and the swapchain's format |
| `docs` | the documentation site |
| `ecs` | the entity component system |
| `editor` | the editor app |
| `files` | writing documents, and reading old versions of them |
| `frames` | frames in flight and what each holds |
| `grid` | grids, their cells, and searches over them |
| `includes` | how headers are named in an include |
| `input` | devices, key events, bindings and commands |
| `interchange` | reading and writing scenes in other tools' formats |
| `lighting` | lights, shadows and lit passes |
| `lit` | the lit renderer's per-object data |
| `loading` | loading in the background |
| `loop` | the main loop's timing |
| `memory` | GPU memory allocation and uploads |
| `meshes` | GPU meshes, and who owns them |
| `models` | model data and its layout |
| `offline` | moya, RIB and the offline renderer |
| `particles` | particle emitters |
| `paths` | file names and their encoding |
| `platform` | the platform layer: SDL and the window |
| `process` | how work moves through the repository: plans, records and reviews |
| `releases` | what ships, and how |
| `rendering` | the realtime renderer's structure |
| `resources` | GPU resource handles and their lifetimes |
| `review` | how a change is reviewed |
| `shaders` | shaders, descriptor sets and bindings |
| `shell` | the shell a game shares: its menu, its text and its look |
| `skinning` | skinned meshes and their joints |
| `swapchain` | the swapchain |
| `testing` | tests and golden images |
| `text` | fonts, and shaping and drawing text |
| `textures` | textures and samplers |
| `tooling` | the scripts, the gates and the developer tools |
| `ui` | `api/ui` |
